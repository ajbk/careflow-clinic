# คู่มือ UAT CareFlow ก่อน Pilot — Journey แบบสองบทบาท

เอกสารนี้ใช้กับเครื่องทดสอบเฉพาะที่และข้อมูลสังเคราะห์เท่านั้น ห้ามบันทึกหรือแสดงข้อมูลผู้ป่วยจริง ข้อมูลทางคลินิกจริง หรือข้อมูลการเงินจริงทุกชนิด การใช้งานจริง การ deploy การสำรอง/กู้คืนข้อมูล และการเชื่อมต่อออกนอกเครื่องถูกปิดใช้งาน

เปิดหน้าต่างเบราว์เซอร์แยกกันสำหรับบทบาท `ผู้ช่วย` และ `แพทย์` โดยใช้การเข้าถึงในเครื่องที่ผู้ดูแล UAT เตรียมไว้ เอกสารนี้ไม่มีข้อมูลเข้าสู่ระบบ

## หยุด UAT ทั้งหมดทันที

หากพบข้อใดข้อหนึ่งด้านล่าง ให้หยุด **ทั้งชุด UAT** ทันที ไม่ทำ Scenario ถัดไป ไม่แก้ข้อมูล และไม่เริ่มใหม่เอง:

- HTTP 500
- ผู้ช่วยเห็น Clinical Note, การวินิจฉัย, รายละเอียดการรักษา หรือบัตร OPD ของผู้ป่วย
- ยาคงเหลือติดลบ หรือการจอง/ตัดสต็อกทำให้ยอดติดลบ
- ยอดเงินบาทที่หน้าจอไม่ตรงกับยอดที่ Scenario กำหนด
- ปิด Visit ได้ทั้งที่หลักฐาน Charge และการชำระ/ยกเว้นไม่ถูกต้อง
- หลัง restart หลักฐานที่บันทึกแล้วหาย เปลี่ยนแปลง หรือ Journey เปลี่ยนโดยไม่มีการกระทำ

บันทึก HN สังเคราะห์, เวลา, หน้าจอที่พบ และผลที่เห็นใน [checklist.md](checklist.md) แล้วส่งต่อผู้ดูแล UAT โดยไม่เผยแพร่ข้อมูลออกจากเครื่องทดสอบ

## วิธีอ่าน Journey และตรวจบทบาท

ทุกขั้นให้ดู `เส้นทางผู้ป่วย` และกล่อง `งานถัดไป` ก่อนกดปุ่ม การมีลิงก์หรือปุ่มที่เป็นการเขียนข้อมูลต้องตรงกับบทบาทที่ระบุในตารางนี้

| Journey ที่เห็น | ผู้ดำเนินการ | คำสั่งที่ต้องเห็นเฉพาะบทบาทนั้น |
| --- | --- | --- |
| `รอพบแพทย์` | แพทย์ | `เริ่มตรวจ` |
| `รอจัดยา` ที่สต็อกไม่พอ | ผู้ช่วย | `รับยาเข้าคลัง` |
| `กำลังจัดยา` | ผู้ช่วย | `เริ่มเตรียมยา`, `เปิดฉลากยา`, สแกนบาร์โค้ด, `เสร็จสิ้นการเตรียมยา` ตามลำดับ |
| `รอแพทย์ปล่อยยา` | แพทย์ | `ปล่อยยา` |
| `รอส่งมอบยา` | ผู้ช่วย | `ยืนยันส่งมอบยา` |
| `รอยืนยันยอด` | แพทย์ | `ยืนยันยอดเพื่อรับชำระ` หรือ `ยกเว้นเต็มจำนวน` |
| `รอรับชำระ` | ผู้ช่วยสำหรับเงินสด | `ยืนยันรับเงินสด … บาท` |
| `พร้อมปิด Visit` | แพทย์ | `ปิด Visit` และหลังปิด `เปิดบัตร OPD` |

ระหว่างทุกจุดส่งต่อ ให้ตรวจหน้าต่างอีกบทบาทด้วย: ต้องเห็นข้อความรอผู้รับผิดชอบ แต่ต้องไม่เห็นปุ่ม/ลิงก์เขียนข้อมูลของอีกบทบาท หากเห็นคำสั่งผิดบทบาท ให้หยุด UAT ทั้งหมดตามกติกาด้านบน

## ข้อมูลสังเคราะห์ที่ใช้ร่วมกัน

- ยา: `[DEMO] ยาทดสอบชนิด A` (`DEMO-MED-001`)
- บาร์โค้ด: `CF-DEMO-001`
- SOAP: ใช้ข้อความ `ข้อมูลสังเคราะห์ UAT` ต่อท้ายชื่อช่อง
- การวินิจฉัย: `การวินิจฉัยสังเคราะห์ UAT`
- ผู้จำหน่าย: `ผู้จำหน่ายสังเคราะห์ UAT`

ใช้ HN ที่ระบบสร้างเท่านั้น และบันทึก HN นั้นใน checklist เพื่อจับคู่หลักฐานในแต่ละ Scenario

## Scenario 1 — ORDER, ตัวบล็อกสต็อก, เงินสด 115 บาท และ restart

### 1. Intake และส่งต่อแพทย์

1. ผู้ช่วยเปิด `รับผู้ป่วย` กด `สร้างผู้ป่วยสังเคราะห์` เลือกตัวเลือกประวัติแพ้ยา `ไม่แพ้` ใส่ `อาการสังเคราะห์ UAT ORDER` ใน `อาการสำคัญ *` แล้วกด `ส่งพบแพทย์`.

   **Journey ที่คาดหวัง:** `รอพบแพทย์`; `งานถัดไป` คือ `เริ่มตรวจ` สำหรับแพทย์ และประวัติแพ้ยาที่เห็นเป็นคำไทยว่าไม่แพ้

2. ขณะที่ Visit ยังเป็น `รอพบแพทย์` ให้ตรวจทั้งสองหน้าต่าง: ผู้ช่วยต้องไม่เห็น `เริ่มตรวจ`; แพทย์ต้องเห็น `เริ่มตรวจ` บนบัตร HN เดียวกัน.

   **Journey ที่คาดหวัง:** ยังเป็น `รอพบแพทย์`; ไม่มีการเปลี่ยนสถานะจากการอ่าน Journey

3. แพทย์กด `เริ่มตรวจ` เติม SOAP ทั้งสี่ช่องและ `การวินิจฉัย` ด้วยข้อมูลสังเคราะห์ กด `สั่งยาจากรายการทดสอบ`, เลือก `[DEMO] ยาทดสอบชนิด A`, ใส่ `จำนวน` เป็น `3`, ใส่วิธีใช้สังเคราะห์, กด `บันทึกร่าง`, `ลงนามและส่งต่อ`, แล้ว `ยืนยันการลงนาม`.

   **Journey ที่คาดหวัง:** เปลี่ยนจาก `กำลังตรวจ` เป็น `รอจัดยา`; เห็นหลักฐาน Clinical Note และหลักฐานการตัดสินใจยาที่ลงนามในหน้าของแพทย์เท่านั้น

### 2. ตัวบล็อกสต็อกและการกู้คืน

4. ผู้ช่วยเปิดหน้าจัดยาของ Visit ที่เพิ่งลงนามโดยยังไม่รับยาเข้าคลัง.

   **Journey ที่คาดหวัง:** `รอจัดยา` พร้อมตัวบล็อกที่ระบุ `ต้องการ 3 เม็ด`, `พร้อมใช้ 0 เม็ด`, `ขาด 3 เม็ด`; ผู้ช่วยเห็น `รับยาเข้าคลัง` แต่ไม่เห็น `เริ่มเตรียมยา`

5. แพทย์เปิด Visit เดียวกันในหน้าจัดยาในขณะที่ตัวบล็อกยังอยู่.

   **Journey ที่คาดหวัง:** ยังเป็น `รอจัดยา`; เห็นข้อความรอผู้ช่วยรับยาเข้าคลัง แต่ไม่มีลิงก์ `รับยาเข้าคลัง` และไม่มี `เริ่มเตรียมยา`

6. ผู้ช่วยกด `รับยาเข้าคลัง` จากตัวบล็อก (ต้องกลับมาที่ Visit เดิมหลังบันทึก) เลือก `[DEMO] ยาทดสอบชนิด A`, ใส่จำนวน `10`, ผู้จำหน่ายสังเคราะห์, ล็อต `UAT-ORDER-LOT`, วันหมดอายุในอนาคต แล้วกด `ยืนยันการรับยา`.

   **Journey ที่คาดหวัง:** กลับสู่ Visit เดิมที่ `รอจัดยา`; ตัวบล็อกหาย และผู้ช่วยเห็น `เริ่มเตรียมยา`

### 3. เตรียม, ปล่อย และส่งมอบยา

7. ผู้ช่วยกด `เริ่มเตรียมยา` แล้วกดลิงก์ที่เห็นว่า `เปิดฉลากยา`; ในหน้า Label กด `บันทึกคำขอพิมพ์และเปิดหน้าต่างพิมพ์` แล้วกลับหน้าจัดยา.

   **Journey ที่คาดหวัง:** `กำลังจัดยา`; มีข้อความ `บันทึกคำขอพิมพ์แล้ว`; Label มีรายการยาและวิธีใช้สังเคราะห์

8. ผู้ช่วยใส่ `CF-DEMO-001` ใน `สแกนบาร์โค้ดยา` แล้วกด **Enter** (ไม่ใช่เพียงกรอกรหัส) ตรวจว่า allocation เป็น `ยืนยันแล้ว` จึงกด `เสร็จสิ้นการเตรียมยา`.

   **Journey ที่คาดหวัง:** เปลี่ยนเป็น `รอแพทย์ปล่อยยา`; ผู้ช่วยไม่เห็น `ปล่อยยา`

9. แพทย์เปิด Visit เดียวกันและกด `ปล่อยยา`.

   **Journey ที่คาดหวัง:** เปลี่ยนเป็น `รอส่งมอบยา`; แพทย์ไม่เห็น `ยืนยันส่งมอบยา`

10. ผู้ช่วยเปิด Visit เดียวกันและกด `ยืนยันส่งมอบยา`.

    **Journey ที่คาดหวัง:** เปลี่ยนเป็น `รอยืนยันยอด`; หน้าคลังแสดงล็อต `UAT-ORDER-LOT` เหลือ 7 เม็ด, จอง 0, พร้อมใช้ 7 และมี Dispense เพียงหนึ่งรายการ

### 4. Charge, Cash, Closure และ OPD

11. แพทย์เปิด `ชำระเงิน` และกด `ยืนยันยอดเพื่อรับชำระ`.

    **Journey ที่คาดหวัง:** `รอรับชำระ`; ยอดรวมและยอดที่ต้องชำระแสดง **115 บาท**; ผู้ช่วยยังไม่เห็นคำสั่งยืนยันยอด

12. ผู้ช่วยกด `ยืนยันรับเงินสด 115 บาท`.

    **Journey ที่คาดหวัง:** `พร้อมปิด Visit`; สถานะรับชำระเป็น `รับเงินสดแล้ว`; แพทย์เป็นผู้เดียวที่เห็น `ปิด Visit`

13. แพทย์กด `ปิด Visit` แล้วเปิด `เปิดบัตร OPD`.

    **Journey ที่คาดหวัง:** `ปิด Visit แล้ว`; บัตร OPD เปิดเฉพาะหน้าต่างแพทย์และแสดงยอดเงินสด 115 บาท ผู้ช่วยต้องไม่เห็นเนื้อหาทางคลินิกหรือบัตร OPD

14. ให้ผู้ดูแลทำ planned restart ตาม [admin-runbook.md](admin-runbook.md) โดยใช้ไฟล์ UAT เดิม จากนั้นแพทย์เปิด HN เดิมและ `เปิดบัตร OPD`; ผู้ช่วยเปิด Journey ของ Visit เดิม.

    **Journey ที่คาดหวัง:** ยังเป็น `ปิด Visit แล้ว`; Allergy, Charge 115 บาท, Cash, Closure, stock และ OPD ที่บันทึกแล้วเหมือนก่อน restart และการเปิด Journey อย่างเดียวต้องไม่สร้างรายการใหม่

## Scenario 2 — `แพ้` สองรายการและสรุปภาษาไทยหลัง restart

1. ผู้ช่วยสร้างผู้ป่วยสังเคราะห์ใหม่ เลือก `แพ้`, กรอก `เพนิซิลลิน` / `ผื่น` ในรายการแรก, กด `เพิ่มรายการแพ้`, กรอก `ไอบูโพรเฟน` / `หายใจลำบาก` ในรายการที่สอง, ใส่ `อาการสังเคราะห์ UAT แพ้ยา` และกด `ส่งพบแพทย์`.

   **Journey ที่คาดหวัง:** `รอพบแพทย์`; บัตรคิวและบริบทผู้ป่วยสรุปประวัติแพ้ยาเป็นภาษาไทย และมีรายการแพ้สองรายการ

2. ขณะที่ยังเป็น `รอพบแพทย์` ตรวจบทบาท: แพทย์เห็น `เริ่มตรวจ`; ผู้ช่วยไม่เห็น `เริ่มตรวจ`.

   **Journey ที่คาดหวัง:** ยังเป็น `รอพบแพทย์`

3. ให้ผู้ดูแลทำ planned restart ด้วยไฟล์ UAT เดิม แล้วแพทย์กด `เริ่มตรวจ` สำหรับ HN นี้.

   **Journey ที่คาดหวัง:** `กำลังตรวจ`; หน้า Consultation แสดงสรุปภาษาไทยของ `แพ้` พร้อมทั้ง `เพนิซิลลิน`/`ผื่น` และ `ไอบูโพรเฟน`/`หายใจลำบาก` ไม่ใช่รหัสสถานะภายใน

4. ไม่ต้องดำเนินการรักษาจริงใน Scenario นี้ ให้กลับคิวโดยไม่บันทึกร่าง.

   **Journey ที่คาดหวัง:** ยังคง `กำลังตรวจ`; หลักฐานแพ้ที่บันทึกแล้วคงอยู่ และไม่มีการสร้างคำสั่งยา, Charge, หรือการตัดสต็อก

## Scenario 3 — `ไม่แพ้`, NO_MEDICATION และ full waiver

1. ผู้ช่วยสร้างผู้ป่วยสังเคราะห์ใหม่ เลือก `ไม่แพ้`, ใส่ `อาการสังเคราะห์ UAT ไม่สั่งยา`, แล้วกด `ส่งพบแพทย์`.

   **Journey ที่คาดหวัง:** `รอพบแพทย์`; แพทย์เห็น `เริ่มตรวจ`, ผู้ช่วยไม่เห็น

2. แพทย์กด `เริ่มตรวจ`, เติม SOAP และการวินิจฉัยสังเคราะห์, กด `ไม่สั่งยา`, ใส่เหตุผลสังเคราะห์, กด `บันทึกร่าง`, `ลงนามและส่งต่อ`, แล้ว `ยืนยันการลงนาม`.

   **Journey ที่คาดหวัง:** ข้าม `เตรียมยา` และ `ส่งมอบยา` เป็น `ข้ามแล้ว`; Visit ไปที่ `รอยืนยันยอด` โดยไม่มี `เปิดฉลากยา` หรือ `เริ่มเตรียมยา`

3. ขณะที่อยู่ `รอยืนยันยอด` ผู้ช่วยเปิดหน้าชำระเงินก่อน.

   **Journey ที่คาดหวัง:** ผู้ช่วยไม่เห็น `ยืนยันยอดเพื่อรับชำระ` และไม่เห็น `ยกเว้นเต็มจำนวน`; แพทย์เห็นคำสั่งเหล่านี้

4. แพทย์กด `ยกเว้นเต็มจำนวน`, ใส่เหตุผลสังเคราะห์ใน `เหตุผลการยกเว้น`, แล้วกด `ยืนยันยกเว้นเต็มจำนวน`.

   **Journey ที่คาดหวัง:** `พร้อมปิด Visit`; สถานะรับชำระเป็น `ยกเว้นเต็มจำนวน · ไม่ต้องรับชำระ`; ขั้นตอนรับเงินถูกข้าม และไม่มีคำสั่งรับเงินสด

5. แพทย์กด `ปิด Visit` แล้วเปิด `เปิดบัตร OPD`.

   **Journey ที่คาดหวัง:** `ปิด Visit แล้ว`; ไม่มี Reservation หรือ Dispense ของ HN นี้ และผู้ช่วยไม่มีสิทธิ์เปิด Clinical/OPD

## Scenario 4 — แข่งกันใช้ล็อตสุดท้าย

1. สร้าง Visit สังเคราะห์สอง Visit แยกกัน โดยในแต่ละ Visit ผู้ช่วยเลือก `ไม่แพ้`, ส่งพบแพทย์, แพทย์กด `เริ่มตรวจ`, บันทึก ORDER ของ `[DEMO] ยาทดสอบชนิด A` จำนวน 1 และลงนาม.

   **Journey ที่คาดหวัง:** ทั้งสอง Visit อยู่ `รอจัดยา`; ผู้ช่วยเป็นผู้เดียวที่เห็น `เริ่มเตรียมยา`

2. ผู้ช่วยรับเข้าล็อตใหม่เพียง 1 เม็ด (เช่น `UAT-RACE-LAST-LOT`) และเปิดหน้าจัดยาของสอง Visit ในหน้าต่างผู้ช่วยสองหน้าต่าง.

   **Journey ที่คาดหวัง:** ทั้งสองยังเป็น `รอจัดยา` และต่างเห็น `เริ่มเตรียมยา`

3. กด `เริ่มเตรียมยา` หนึ่งครั้งในแต่ละหน้าต่างให้ใกล้เคียงกันที่สุด ห้ามกดซ้ำหรือกด retry อัตโนมัติ.

   **Journey ที่คาดหวัง:** มีเพียง Visit เดียวเป็น `กำลังจัดยา`; อีก Visit ต้องกลับ/คงที่ `รอจัดยา` พร้อมตัวบล็อก `ขาด 1 เม็ด` และไม่มี `เริ่มเตรียมยา` จนกว่าจะมีการรับสต็อกจริง ยอดคงเหลือต้องไม่ติดลบ

## Scenario 5 — session expiry ระหว่าง Visit

1. ผู้ช่วยสร้าง Visit สังเคราะห์และเลือก `ไม่แพ้`; แพทย์กด `เริ่มตรวจ` และพิมพ์ข้อความสังเคราะห์ใน SOAP แต่ **ยังไม่กด** `บันทึกร่าง`.

   **Journey ที่คาดหวัง:** `กำลังตรวจ`; มีเพียง Intake/Allergy ที่บันทึกแล้วบนเซิร์ฟเวอร์ ไม่มี Clinical Note ที่ลงนาม

2. ให้ผู้ดูแลใช้ตัวควบคุม session-expiry ของ UAT ที่ได้รับอนุมัติ แล้วให้แพทย์ reload หน้าห้องตรวจและกลับเข้าสู่ระบบตามขั้นตอนในเครื่อง.

   **Journey ที่คาดหวัง:** กลับสู่ Visit เดิมพร้อมข้อความ `เซสชันหมดอายุ งานยังไม่ได้ถูกบันทึก`; ข้อความ SOAP ที่ยังไม่บันทึกต้องไม่ปรากฏเป็นหลักฐาน และ Intake/Allergy ที่บันทึกแล้วต้องยังอยู่

3. ผู้ช่วยเปิด Journey ของ Visit เดียวกันหลังแพทย์กลับมา.

   **Journey ที่คาดหวัง:** ยังเป็น `กำลังตรวจ`; ไม่มี Clinical prose หรือ hash ของแพทย์รั่วสู่หน้าผู้ช่วย และการอ่าน Journey ไม่สร้างการเขียนข้อมูล

## ปิดชุด UAT

ก่อนสรุปผล ให้ตรวจทุกช่องใน checklist ว่ามี PASS/FAIL/BLOCKED และ HN สังเคราะห์กำกับ หากไม่มีเหตุหยุดบังคับ ผู้ดูแลจึงหยุด host ตาม runbook ได้ ห้ามใช้คำสั่ง reset เพื่อกลบผล UAT และห้ามนำฐานข้อมูล UAT ไปใช้เป็น backup, deployment หรือข้อมูลจริง
