# คู่มือทดลอง CareFlow ก่อน Pilot

เอกสารนี้ใช้กับข้อมูลสังเคราะห์เท่านั้น และให้บันทึกผลทุกครั้งลงใน checklist ที่อ้างถึงท้ายแต่ละขั้นตอน

## กติกาก่อนเริ่ม

- ใช้เฉพาะผู้ป่วยสังเคราะห์ที่สร้างจากปุ่ม `สร้างผู้ป่วยสังเคราะห์` เท่านั้น
- เปิดทำ Scenario A, B และ C ตามลำดับ เพื่อให้ Scenario B ใช้ยอดคงเหลือจากล็อต `UAT-A-LATE` ของ Scenario A
- ทุกครั้งที่เห็นผลไม่ตรงกับสถานะที่คาดหวัง ให้หยุดที่จุดนั้นและบันทึกผลก่อนดำเนินการต่อ
- อย่าใส่ชื่อ เบอร์โทรศัพท์ หรือข้อมูลสุขภาพของบุคคลจริงลงในช่องใด ๆ

### ค่าข้อมูลสังเคราะห์ที่ต้องใช้

| รายการ | Scenario A | Scenario B | Scenario C |
| --- | --- | --- | --- |
| อาการสำคัญ | `อาการสังเคราะห์ UAT เงินสด` | `อาการสังเคราะห์ UAT ปฏิเสธและพร้อมเพย์` | `อาการสังเคราะห์ UAT ไม่สั่งยา` |
| ประวัติแพ้ยา | `NONE_KNOWN` | `NONE_KNOWN` | `UNKNOWN` |
| SOAP | `ข้อมูลสังเคราะห์ UAT` ต่อท้ายชื่อช่อง Subjective, Objective, Assessment และ Plan | ใช้ค่าเดียวกับ Scenario A | ใช้ค่าเดียวกับ Scenario A |
| การวินิจฉัย | `การวินิจฉัยสังเคราะห์ UAT` | ใช้ค่าเดียวกับ Scenario A | ใช้ค่าเดียวกับ Scenario A |
| การตัดสินใจยา | `ORDER` | `ORDER` | `NO_MEDICATION` |
| ยา | `[DEMO] ยาทดสอบชนิด A` | `[DEMO] ยาทดสอบชนิด A` | ไม่มี |
| จำนวน | `8` | `1` | ไม่มี |
| วิธีใช้หรือเหตุผล | `รับประทานตามคำแนะนำสังเคราะห์ UAT` | `รับประทานตามคำแนะนำสังเคราะห์ UAT` | `ไม่มีข้อบ่งใช้ยาในการทดสอบสังเคราะห์` |
| การชำระหรือยกเว้น | เงินสด `140` บาท | PromptPay `UAT-PROMPT-105` | ยกเว้นเต็มจำนวน `100` บาท ด้วยเหตุผล `ยกเว้นเพื่อทดสอบระบบสังเคราะห์` |

สำหรับ Scenario A ให้ใช้ยา `DEMO-MED-001` สองล็อตจากผู้จำหน่าย `ผู้จำหน่ายสังเคราะห์ UAT`: ล็อต `UAT-A-EARLY` จำนวน `5` หมดอายุ `2031-12-31` และล็อต `UAT-A-LATE` จำนวน `10` หมดอายุ `2032-12-31` ผล FEFO ที่คาดหวังคือ `5 + 3`; หลังส่งมอบ ยอดคงเหลือในสองล็อตต้องเป็น `0 + 7` ตามลำดับ

## การเปิดสองหน้าต่างและตรวจบทบาท

1. เปิดหน้าต่าง Assistant แล้วเลือกเมนู `รับผู้ป่วย`; เปิดหน้าต่าง Doctor แล้วเลือกเมนู `คิวผู้ป่วย` และตรวจว่าหัวพื้นที่ทำงานแสดง `งานผู้ช่วย` กับ `งานแพทย์` ตามลำดับ
   **สถานะที่คาดหวัง:** ทั้งสองหน้าต่างพร้อมใช้งานตามบทบาท และไม่มีข้อมูลบุคคลจริงแสดงอยู่
   **Checklist:** `PRE-01`

2. ในหน้าต่าง Assistant เลือกเมนู `คิวผู้ป่วย`; ในหน้าต่าง Doctor เลือกเมนู `คิวผู้ป่วย` เพื่อยืนยันว่าทั้งสองหน้าต่างเห็นคิวเดียวกัน
   **สถานะที่คาดหวัง:** หน้าต่างทั้งสองแสดงคิวผู้ป่วย และคำสั่งที่เห็นแตกต่างตามบทบาท
   **Checklist:** `PRE-02`

## Scenario A — สั่งยา 8 เม็ด, FEFO สองล็อต, เงินสด 140 บาท

1. ในหน้าต่าง Assistant ที่เมนู `รับผู้ป่วย` กด `สร้างผู้ป่วยสังเคราะห์`
   **สถานะที่คาดหวัง:** เห็น Patient Header ที่มี `HN DEMO-` และเป็นข้อมูลสังเคราะห์
   **Checklist:** `A-01`

2. ที่ช่อง `อาการสำคัญ *` ใส่ `อาการสังเคราะห์ UAT เงินสด` แล้วกด `ส่งพบแพทย์`
   **สถานะที่คาดหวัง:** รายการอยู่ใน `คิวผู้ป่วย` สถานะ `WAITING` หรือป้าย `รอตรวจ`
   **Checklist:** `A-02`

3. บนบัตรคิว กด `ทบทวนข้อมูลแพ้ยา`; ในหน้าต่าง `ทบทวนประวัติแพ้ยา` เลือก `NONE_KNOWN` แล้วกด `บันทึกการทบทวน`
   **สถานะที่คาดหวัง:** หน้าต่างทบทวนปิดลง และประวัติแพ้ยาเป็น `NONE_KNOWN` ขณะที่ Visit ยังรอตรวจ
   **Checklist:** `A-03`

4. ในหน้าต่าง Doctor ที่ `คิวผู้ป่วย` กด `เริ่มการตรวจ` บนบัตรของ Scenario A
   **สถานะที่คาดหวัง:** เปิดห้องตรวจและสถานะเป็น `CONSULTING` หรือป้าย `กำลังตรวจ`
   **Checklist:** `A-04`

5. ในห้องตรวจ ใส่ค่า SOAP ดังนี้: `Subjective (ข้อมูลจากผู้ป่วย)` = `ข้อมูลสังเคราะห์ UAT Subjective`, `Objective (ผลตรวจ)` = `ข้อมูลสังเคราะห์ UAT Objective`, `Assessment (การประเมิน)` = `ข้อมูลสังเคราะห์ UAT Assessment`, `Plan (แผนการดูแล)` = `ข้อมูลสังเคราะห์ UAT Plan`; ที่ `การวินิจฉัย` ใส่ `การวินิจฉัยสังเคราะห์ UAT`
   **สถานะที่คาดหวัง:** ข้อมูลยังอยู่ในห้องตรวจ สถานะ `CONSULTING` และไม่มีข้อความเตือนว่าข้อมูล SOAP หรือการวินิจฉัยไม่ครบ
   **Checklist:** `A-05`

6. กด `สั่งยาจากรายการทดสอบ`, ค้นหาและเลือก `[DEMO] ยาทดสอบชนิด A`, ใส่ `จำนวน` เป็น `8`, ใส่ `วิธีใช้ยา` เป็น `รับประทานตามคำแนะนำสังเคราะห์ UAT`, แล้วกด `บันทึกร่าง`
   **สถานะที่คาดหวัง:** ร่างแสดง ORDER ของ `[DEMO] ยาทดสอบชนิด A` จำนวน 8 เม็ด และห้องตรวจยังเป็น `CONSULTING`
   **Checklist:** `A-06`

7. กด `ลงนามและส่งต่อ` แล้วกด `ยืนยันการลงนาม` ในหน้าต่างยืนยัน
   **สถานะที่คาดหวัง:** เห็น `หลักฐานการตัดสินใจยา ที่ลงนาม` และ Visit เป็น `AWAITING_PREPARATION` หรือป้าย `รอจัดยา`
   **Checklist:** `A-07`

8. ในหน้าต่าง Assistant เลือกเมนู `คลังยา`, กด `รับยาเข้าคลัง`, ค้นหาและเลือก `[DEMO] ยาทดสอบชนิด A`, ใส่ `จำนวนที่รับ` `5`, `ผู้ผลิต / ผู้จัดจำหน่าย` `ผู้จำหน่ายสังเคราะห์ UAT`, `เลขที่ล็อต` `UAT-A-EARLY`, `วันหมดอายุ` `2031-12-31`, แล้วกด `ยืนยันการรับยา`
   **สถานะที่คาดหวัง:** ล็อต `UAT-A-EARLY` แสดงคงคลัง 5 และพร้อมใช้ 5
   **Checklist:** `A-08`

9. กด `รับยาเข้าคลัง` อีกครั้ง แล้วเลือก `[DEMO] ยาทดสอบชนิด A`; ใส่ `จำนวนที่รับ` `10`, `ผู้ผลิต / ผู้จัดจำหน่าย` `ผู้จำหน่ายสังเคราะห์ UAT`, `เลขที่ล็อต` `UAT-A-LATE`, `วันหมดอายุ` `2032-12-31`, แล้วกด `ยืนยันการรับยา`
   **สถานะที่คาดหวัง:** ล็อต `UAT-A-LATE` แสดงคงคลัง 10 และพร้อมใช้ 10
   **Checklist:** `A-09`

10. กลับไปที่รายการของ Scenario A แล้วกด `เริ่มเตรียมยา`
    **สถานะที่คาดหวัง:** Visit เป็น `PREPARING` หรือป้าย `กำลังจัดยา`; รายการจองต้องใช้ `UAT-A-EARLY` 5 เม็ด และ `UAT-A-LATE` 3 เม็ดตามลำดับ FEFO
    **Checklist:** `A-10`

11. เปิดฉลากปัจจุบัน แล้วกด `บันทึกคำขอพิมพ์และเปิดหน้าต่างพิมพ์`
    **สถานะที่คาดหวัง:** เห็นข้อความ `บันทึกคำขอพิมพ์แล้ว` และฉลากแสดง `[DEMO] ยาทดสอบชนิด A` จำนวน 8 เม็ดพร้อมวิธีใช้ที่กำหนด
    **Checklist:** `A-11`

12. กลับหน้าจัดยา ใช้ช่อง `สแกนบาร์โค้ดยา` ใส่ `CF-DEMO-001` แล้วกดยืนยันซ้ำให้ครบทั้งสองล็อต
    **สถานะที่คาดหวัง:** การยืนยันทั้งสองรายการสำเร็จ และ Visit ยังเป็น `PREPARING`
    **Checklist:** `A-12`

13. กด `เสร็จสิ้นการเตรียมยา`
    **สถานะที่คาดหวัง:** Visit เป็น `AWAITING_RELEASE` หรือป้าย `รอแพทย์ปล่อยยา`
    **Checklist:** `A-13`

14. ในหน้าต่าง Doctor เปิดรายการจัดยาและกด `ปล่อยยา`
    **สถานะที่คาดหวัง:** Visit เป็น `AWAITING_HANDOFF` หรือป้าย `รอส่งมอบยา`
    **Checklist:** `A-14`

## จุดพักเพื่อ restart ระบบ

หลัง `A-14` ให้หยุดที่สถานะ `AWAITING_HANDOFF` และขอให้ผู้ดูแลระบบทำ restart ตามขั้นตอนภายในของทีม โดยไม่แก้ไขข้อมูล UAT ใด ๆ เมื่อหน้าจอพร้อมอีกครั้ง ให้ Assistant กลับมาดำเนินการต่อดังนี้

1. ในหน้าจัดยา กด `ยืนยันส่งมอบยา`
   **สถานะที่คาดหวัง:** Visit เป็น `AWAITING_CHARGE` หรือป้าย `รอคิดเงิน`; `UAT-A-EARLY` เหลือ 0 เม็ด และ `UAT-A-LATE` เหลือ 7 เม็ด
   **Checklist:** `RESTART-01`

2. ในหน้าต่าง Doctor เปิดหน้าชำระเงินแล้วกด `ยืนยันยอดเพื่อรับชำระ`
   **สถานะที่คาดหวัง:** Visit เป็น `AWAITING_PAYMENT` หรือป้าย `รอรับชำระ` และยอดที่แสดงเป็น 140 บาท
   **Checklist:** `A-15`

3. ในหน้าต่าง Assistant กด `ยืนยันรับเงินสด 140 บาท`
   **สถานะที่คาดหวัง:** Visit เป็น `READY_TO_CLOSE` หรือป้าย `พร้อมปิด Visit` และแสดงว่า `รับเงินสดแล้ว`
   **Checklist:** `A-16`

4. ในหน้าต่าง Doctor กด `ปิด Visit`
   **สถานะที่คาดหวัง:** Visit เป็น `CLOSED` และแสดง `ปิด Visit แล้ว`
   **Checklist:** `A-17`

5. กด `เปิดบัตร OPD`
   **สถานะที่คาดหวัง:** บัตร OPD แสดงข้อมูลสังเคราะห์ของ Scenario A และการชำระเงินสด 140 บาท
   **Checklist:** `A-18`

## Scenario B — ปฏิเสธการจัดยา, พิมพ์ใหม่, PromptPay 105 บาท

Scenario B ใช้ `[DEMO] ยาทดสอบชนิด A` ที่เหลือในล็อต `UAT-A-LATE` จาก Scenario A จำนวน 7 เม็ด

1. ในหน้าต่าง Assistant ที่ `รับผู้ป่วย` กด `สร้างผู้ป่วยสังเคราะห์`
   **สถานะที่คาดหวัง:** เห็น Patient Header ที่มี `HN DEMO-` และเป็นข้อมูลสังเคราะห์
   **Checklist:** `B-01`

2. ที่ `อาการสำคัญ *` ใส่ `อาการสังเคราะห์ UAT ปฏิเสธและพร้อมเพย์` แล้วกด `ส่งพบแพทย์`
   **สถานะที่คาดหวัง:** รายการอยู่ใน `คิวผู้ป่วย` สถานะ `WAITING` หรือป้าย `รอตรวจ`
   **Checklist:** `B-02`

3. กด `ทบทวนข้อมูลแพ้ยา`; ใน `ทบทวนประวัติแพ้ยา` เลือก `NONE_KNOWN` แล้วกด `บันทึกการทบทวน`
   **สถานะที่คาดหวัง:** ประวัติแพ้ยาเป็น `NONE_KNOWN` และ Visit ยังรอตรวจ
   **Checklist:** `B-03`

4. ในหน้าต่าง Doctor ที่ `คิวผู้ป่วย` กด `เริ่มการตรวจ`
   **สถานะที่คาดหวัง:** เปิดห้องตรวจและ Visit เป็น `CONSULTING`
   **Checklist:** `B-04`

5. ใส่ `ข้อมูลสังเคราะห์ UAT Subjective`, `ข้อมูลสังเคราะห์ UAT Objective`, `ข้อมูลสังเคราะห์ UAT Assessment`, และ `ข้อมูลสังเคราะห์ UAT Plan` ในช่อง SOAP ที่ตรงกัน; ใส่ `การวินิจฉัยสังเคราะห์ UAT` ที่ `การวินิจฉัย`
   **สถานะที่คาดหวัง:** ข้อมูลอยู่ในห้องตรวจ สถานะ `CONSULTING` และพร้อมบันทึกร่าง
   **Checklist:** `B-05`

6. กด `สั่งยาจากรายการทดสอบ`, เลือก `[DEMO] ยาทดสอบชนิด A`, ใส่ `จำนวน` `1`, ใส่ `วิธีใช้ยา` `รับประทานตามคำแนะนำสังเคราะห์ UAT`, แล้วกด `บันทึกร่าง`
   **สถานะที่คาดหวัง:** ร่างแสดง ORDER จำนวน 1 เม็ด และห้องตรวจยังเป็น `CONSULTING`
   **Checklist:** `B-06`

7. กด `ลงนามและส่งต่อ` แล้วกด `ยืนยันการลงนาม`
   **สถานะที่คาดหวัง:** Visit เป็น `AWAITING_PREPARATION` และเห็นหลักฐานการตัดสินใจยา ที่ลงนาม
   **Checklist:** `B-07`

8. ในหน้าต่าง Assistant กด `เริ่มเตรียมยา`
   **สถานะที่คาดหวัง:** Visit เป็น `PREPARING`; การจองใช้ `UAT-A-LATE` 1 เม็ด
   **Checklist:** `B-08`

9. เปิดฉลากปัจจุบันแล้วกด `บันทึกคำขอพิมพ์และเปิดหน้าต่างพิมพ์`
   **สถานะที่คาดหวัง:** เห็นข้อความ `บันทึกคำขอพิมพ์แล้ว` และ Visit ยังเป็น `PREPARING`
   **Checklist:** `B-09`

10. ที่ `สแกนบาร์โค้ดยา` ใส่ `CF-DEMO-001` แล้วกดยืนยัน จากนั้นกด `เสร็จสิ้นการเตรียมยา`
    **สถานะที่คาดหวัง:** Visit เป็น `AWAITING_RELEASE` หรือป้าย `รอแพทย์ปล่อยยา`
    **Checklist:** `B-10`

11. ในหน้าต่าง Doctor ที่ช่อง `เหตุผลการปฏิเสธ` ใส่ `ทดสอบการพิมพ์ฉลากใหม่` แล้วกด `ปฏิเสธการจัดยา`
    **สถานะที่คาดหวัง:** Visit กลับเป็น `AWAITING_PREPARATION` หรือป้าย `รอจัดยา`
    **Checklist:** `B-11`

12. ในหน้าต่าง Assistant กด `เริ่มเตรียมยา` อีกครั้ง
    **สถานะที่คาดหวัง:** Visit เป็น `PREPARING` และมีข้อความให้พิมพ์ฉลากรอบใหม่
    **Checklist:** `B-12`

13. เปิดฉลากปัจจุบันแล้วกด `บันทึกคำขอพิมพ์และเปิดหน้าต่างพิมพ์`

## Scenario C — ไม่สั่งยา, ยกเว้นเต็มจำนวน 100 บาท

1. ในหน้าต่าง Assistant ที่ `รับผู้ป่วย` กด `สร้างผู้ป่วยสังเคราะห์`
   **สถานะที่คาดหวัง:** เห็น Patient Header ที่มี `HN DEMO-` และเป็นข้อมูลสังเคราะห์
   **Checklist:** `C-01`

   **สถานะที่คาดหวัง:** รายการอยู่ใน `คิวผู้ป่วย` สถานะ `WAITING` หรือป้าย `รอตรวจ`
   **Checklist:** `C-02`

   **สถานะที่คาดหวัง:** ประวัติแพ้ยาเป็น `UNKNOWN` และ Visit ยังรอตรวจ
   **Checklist:** `C-03`

   **สถานะที่คาดหวัง:** เปิดห้องตรวจและ Visit เป็น `CONSULTING`

   **สถานะที่คาดหวัง:** ข้อมูลอยู่ในห้องตรวจ สถานะ `CONSULTING` และพร้อมบันทึกร่าง

   **สถานะที่คาดหวัง:** ร่างแสดง `NO_MEDICATION` พร้อมเหตุผลที่กำหนด และห้องตรวจยังเป็น `CONSULTING`
   **Checklist:** `C-06`

## ตรวจสิทธิ์ Assistant และ Doctor

1. ในหน้าต่าง Assistant เลือก `คิวผู้ป่วย` และตรวจว่าคำสั่ง `เริ่มการตรวจ` ไม่ปรากฏสำหรับ Assistant
   **สถานะที่คาดหวัง:** Assistant เห็นเฉพาะการติดตามคิวและคำสั่งที่ทำได้ตามบทบาท
   **Checklist:** `ROLE-01`

2. ในหน้าต่าง Assistant ที่หน้าชำระเงินของ Visit ที่รอแพทย์ ให้ตรวจว่าปุ่ม `ยืนยัน PromptPay`, `ยกเว้นเต็มจำนวน`, `ปิด Visit`, และ `เปิดบัตร OPD` ไม่ปรากฏ
   **สถานะที่คาดหวัง:** Assistant เห็นข้อความรอแพทย์หรือคำสั่งที่ Assistant ทำได้เท่านั้น
   **Checklist:** `ROLE-02`

3. ในหน้าต่าง Doctor ที่ `คิวผู้ป่วย` ตรวจว่ามี `เริ่มการตรวจ`; ที่หน้าชำระเงินตรวจว่ามี `ยืนยันยอดเพื่อรับชำระ`, `ยืนยัน PromptPay`, `ยกเว้นเต็มจำนวน`, และ `ปิด Visit` ตามสถานะของ Visit
   **สถานะที่คาดหวัง:** Doctor เห็นคำสั่งได้ครบเมื่อ Visit อยู่ในสถานะที่ถูกต้อง
   **Checklist:** `ROLE-03`

## เมื่อใดต้องหยุดทันที

- พบข้อมูลบุคคลจริง หรือข้อมูลของ Scenario หนึ่งไปแสดงในอีก Scenario หนึ่ง
- สถานะหลังปุ่มที่กดไม่ตรงกับคู่มือ, ยอดไม่เป็น 140 บาท / 105 บาท / 100 บาทตาม Scenario, หรือยอดสุทธิของ Scenario C ไม่เป็น 0 บาท
- การเลือกล็อตของ Scenario A ไม่เป็น `5 + 3`, ยอดหลังส่งมอบไม่เป็น `0 + 7`, หรือ Scenario B ใช้ล็อตที่ไม่ตรงกับ `UAT-A-LATE`
- ข้อมูลที่ลงนามแล้วหรือสถานะ `AWAITING_HANDOFF` หายไปหลัง restart ระบบ
- Assistant เห็นหรือทำคำสั่ง Doctor-only ได้, หรือ Doctor ไม่เห็นคำสั่งที่ควรทำได้
- หน้าจอแสดงข้อความผิดพลาด, หยุดตอบสนอง, หรือไม่สามารถบันทึกผลอย่างปลอดภัย

เมื่อเกิดข้อใดข้อหนึ่ง ให้หยุด Scenario นั้นทันที เลือก `FAIL` หรือ `BLOCKED` ใน checklist และเปิดรายการปัญหาโดยไม่พยายามแก้ข้อมูล UAT เอง

## วิธีบันทึก PASS / FAIL / BLOCKED

- เลือก `PASS` เมื่อผลที่เห็นตรงกับ Expected ครบถ้วน
- เลือก `FAIL` เมื่อระบบทำงานต่อได้แต่ผลที่เห็นต่างจาก Expected
- เลือก `BLOCKED` เมื่อไม่สามารถไปต่อได้อย่างปลอดภัย หรือจำเป็นต้องให้ทีมดูแลช่วยตรวจ
- บันทึกเวลา สิ่งที่เห็น หมายเหตุ UX และหลักฐานสังเคราะห์ในรายการเดียวกันทุกครั้ง

1. หลังปิด Scenario ทั้งสาม ให้เลือกเมนู `คิวผู้ป่วย` และตรวจว่าไม่มีบัตรคิวของ Scenario A, B หรือ C เหลืออยู่
   **สถานะที่คาดหวัง:** Scenario ทั้งสามเป็น `CLOSED` และพร้อมสรุปผล UAT
   **Checklist:** `FINAL-01`

ใช้ตารางปัญหาท้าย checklist เพื่อบันทึก `Blocker`, `Important`, หรือ `Minor` พร้อมสิ่งที่พบ สิ่งที่คาดหวัง หลักฐาน และการตัดสินใจของทีม
